# 版本安装与数据兼容验收要求

本文规定 Windows 安装包在版本交付前必须满足的安装、升级、降级和用户数据兼容门槛。脚本模拟、版本号伪装或安装器自身接受覆盖，均不能替代真实程序与数据的双向验收。

## 每个真实版本的验收矩阵

对每个准备交付的新版本，使用该版本的实际安装包和实际程序二进制，在隔离的 Windows 测试环境中完成以下场景：

1. 从每个承诺支持的历史起点执行旧版 → 新版覆盖；从新版 → 每个承诺支持的旧版降级覆盖。覆盖沿用原安装范围和目录，不因目标版本号较低而阻止安装。
2. 每次覆盖后实际启动应用，确认已有用户设置和任务历史可读取；新增或修改设置、任务记录后重启，再确认数据仍可读取。
3. 使用隔离的代表性设置和任务数据，不接触真实用户资料；保留原始素材与已有导出文件，不让安装、迁移或卸载覆盖或删除它们。
4. 若数据格式发生变化，旧版必须继续读取兼容数据；新版独有数据必须保全。覆盖回旧版后验证兼容数据可用，再升回新版并验证新版独有数据仍可用。
5. 验收覆盖承诺支持的历史版本起点，包括跨版本直升与直降，例如实际发布的 0.1.0 与未来实际发布的 0.1.5 或 0.3.0。仅安装器样本使用这些版本字符串，不构成真实版本兼容证据。
6. 记录每个安装包与程序二进制的产品版本、来源提交/构建身份、SHA-256、安装范围、覆盖方向、应用启动及设置/任务数据读写结果。任何启动或数据兼容失败均阻断该版本发布。

版本矩阵应明确历史起点集合。某个起点若仍在支持窗口内，就必须纳入本次矩阵；不能只测相邻小版本而推断可跨版本直升或直降。测试在可还原的虚拟机快照或专用隔离环境中执行，不能把测试数据写入当前用户真实配置、任务记录、原始素材或导出目录。

## 首次安装、覆盖与卸载

- 首次安装必须从干净用户状态开始，不得读取开发版或测试运行目录产生的设置及任务历史。
- 正常升级、同版本重装和降级覆盖沿用原安装范围及目录，保留用户设置和任务历史。目标版本较低本身不是拒绝覆盖的理由。
- 卸载界面应分别提供“保留设置”和“保留任务历史”选项，互不绑定，且默认均为保留。卸载不得删除原始素材或用户导出文件。
- 安装器测试还应检查版本识别、范围与目录沿用、文件关联和旧组件保留/回滚；这些安装器行为测试不替代实际应用启动与数据读写验证。
