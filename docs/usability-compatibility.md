## 本轮实测

Windows 11 x64、Qt 6.12 Release、D3D11。应用与桌面测试程序均已构建。在同一台显示器上分别按系统 150% 和 Qt 等效 100%、200% 运行，窗口采集记录的 DPR 分别为 1.5、1.0、2.0。三组均通过以下四项桌面回归。

- 用两个不同目录的 PNG 测试正向及反向切换、关闭当前文件、关闭最后一个文件并返回浏览。
- 在 1600 × 900 与 820 × 620 逻辑尺寸下操作素材浏览器，检查窄窗选择摘要与源路径一致，并采集窗口截图。
- 通过键盘进入桌面目录，检查后退和前进时的目录、选择与滚动位置。
- 检查设置页的导航及草稿行为。

以上覆盖单屏布局。双屏迁移结果见下节，跨显卡解码仍待实机验证。

## 视频重播、键盘与播放列表

视频自然播完会保留最后一帧。此时按空格或点击播放按钮，从零秒继续使用同一播放会话。点击静音等播放控件后可以直接按空格切换播放。输入时间和操作弹出菜单时，键盘交给当前输入框或菜单。

播放列表标题旁的按钮可以切换视图，选择会保存在视频偏好设置中。紧凑列表的行高从 56 降为 32 个逻辑像素。缩略图列表的行高为 44，显示视频画面、文件名和当前项的时长。后台按需解码并缓存画面，暂时取不到画面时显示视频类型图标。

Windows 11、Qt 6.12 Release 实测使用一段 60 秒的 H.264 视频，确认单文件播完后按空格从片头继续，点击静音后连续两次按空格能暂停和恢复，静音状态保持。跳转时间输入框打开时也检查了空格的归属。另用 18 个带中文文件名的片段验证视图切换、真实缩略图和按行选片。缩略图测试覆盖缓存命中、文件被替换、大于 128 MiB 的文件、损坏文件和省略可选 FFmpeg 的构建。

实测发现，时间轴原先按完整可用宽度绘制，而滑块的实际行程还要扣除手柄宽度。现在轨道、进度、悬停时间与 A/B 端点共用手柄中心的行程。两组跨屏用例及原有素材导航、视频定位快捷键回归均通过。测试后通过 Windows API 复查，两屏均已恢复为 144 DPI（150%）。

复测时，在设置了不同缩放的 Windows 扩展桌面上，准备带 libmpv 的 Release 桌面测试程序，将 `FORMAVIEW_UI_TEST_ROOT` 指向可写证据目录，设置 `FORMAVIEW_TEST_MONITOR_DRAG=1`，在前台运行 `formaview_desktop_tests.exe mixedDpiWorkspaceDrag`。用例核对 HWND 与 Qt 报告的 DPI，并记录各屏窗口截图。首轮日志和截图在验收暂存区 `verification/MixedDpi-20261125/final-200` 和 `final-125` 对应目录及同名日志中。

### 原生文件选择、全屏播放与副屏移除

同一组双 4K 显示器，主屏 150%，副屏分别为 125% 和 200%。每次从主屏拖到副屏，再拖回主屏，通过 Ctrl+O 打开 Windows 文件选择器。用例检查系统对话框（`#32770`）的原生所有者、所在显示器和 DPI，并从对话框取消返回。视频检查使用同一段 60 秒样片，在两屏分别点击控制栏进入和退出全屏，核对全屏边界、普通窗口位置、播放状态和时间轴落点。

实测发现两个问题。退出全屏时，Qt 重建原生标题栏，前台焦点可能留在标题栏辅助窗口。现在窗口边框恢复后会重新激活播放器。另一个问题发生在副屏全屏期间断开输出后。原先从 200% 副屏回到 150% 主屏并退出全屏，1200 × 740 的窗口变成 1600 × 987。现在保存窗口位置时同时记录显示器和 DPI，原屏已移除时按当前 DPI 换算尺寸，居中放回可用工作区。

副屏移除通过 Windows 显示配置 API 暂停副屏的活动输出路径，系统从双屏扩展切为仅主屏。此方法覆盖显示器从 Windows 和 Qt 的活动列表消失、窗口迁移及迁移后的操作。线缆、转接器及驱动重新握手需要物理拔插另测。

| 复测场景 | 验收结果 |
|---|---|
| 从主屏或副屏唤起“打开文件” | 对话框始终属于当前 FormaView 窗口，Windows 报告的显示器和 DPI 与所属窗口相同。取消后焦点回到原工作区。 |
| 在两屏分别进入、退出全屏 | 全屏覆盖当前显示器。窗口恢复到原来的位置和尺寸。两种状态下均可点击播放、暂停；全屏点击轨道中点定位到 30 秒，退出后点击四分之一处定位到 15 秒。 |
| 125% 副屏，普通窗口中移除输出 | 窗口回到 150% 主屏工作区，保持 1200 × 740 逻辑像素，播放及时间轴仍可操作。 |
| 200% 副屏，全屏中移除输出 | 视频回到 150% 主屏并覆盖全屏；点击退出后恢复为 1200 × 740，位于主屏工作区内。再次播放、暂停和定位均通过。 |

复测移除场景时，在上述命令基础上将 `FORMAVIEW_TEST_REMOVE_SECONDARY` 设为 `windowed` 或 `full`，并使用新的证据目录。看到该目录中的 `ready-to-remove-secondary` 后，在 60 秒内从系统断开副屏，保持单屏直到用例退出。用例验证主屏内的窗口边界、恢复尺寸以及真实鼠标操作。

本轮证据在 `verification/MixedDpi-Picker-Fullscreen-20261125`。其中 `release-window125` 和 `release-full200` 保存窗口截图与尺寸记录，同名日志记录原生对话框位置、点击坐标和测试结果，`*-topology.log` 记录测试前、移除后及恢复后的显示配置。

2026-11-25，在 Windows Sandbox 中从管理员组移除来宾账户，再用新登录令牌运行 v0.1.2 正式安装包和 v0.2.0 开发安装包。令牌包含 Users 组和 Medium 完整性级别。两个安装器使用同一账户的默认安装目录。

旧开发包 `8c2f640` 有一个可复现的问题。测试账户原本双击 `.pskx` 会直接打开已有的第三方查看器。升级时勾选该格式后，原打开命令仍在，双击却出现了应用选择器。单独撤掉 FormaView 的 `OpenWithProgids` 候选可以恢复 Windows 查询到的处理程序，但实际双击仍可能出现选择器。撤掉对应的 `Capabilities\FileAssociations` 登记后，第三方查看器才直接收到文件。Windows 会在新程序登记文件类型后提示用户选择应用。[Windows 默认应用机制](https://learn.microsoft.com/en-us/windows/apps/develop/windows-integration/default-apps-platform)

修复后的按用户安装保留已有的第三方传统打开命令。遇到这类关联时，安装器跳过上述两项候选登记，保留 FormaView 自己的类型说明、分类图标和打开命令。用户仍可右键文件，通过“打开方式”选择程序。修复安装只清理所有权账本中与当前值相符的旧候选。

## 自定义快捷键与视频片段循环

“软件设置 → 快捷键”按工作区、视频、图片和模型分组。点击键位后按新组合，Backspace 清空该项，Esc 取消录入。保存后立即生效，下次启动会读取已保存的键位。同一组合可分别用于图片和视频，在同一场景中重复绑定时会提示已经占用该组合的操作。

视频逐帧默认使用 D、F。播放或暂停时按 Q 标记起点，移动到更晚的位置按 E 标记终点，播放到终点后会回到起点。W 清除两个标记并继续正常播放。重新按 Q 可以替换起点。播放菜单显示当前键位和两个端点的时间。静音、外挂字幕、全屏、小窗和切换视频也可在设置页绑定。

Windows 桌面回归用例 `videoLoopShortcutSettings` 使用带时间轴的真实视频，覆盖设置循环、实际回跳、清除后越过终点、拒绝冲突、改键保存以及恢复默认。此外，使用本机 60 fps 的长 FLV 验证了远距离跳转后按 F 前进一帧、按 D 返回原帧及恢复播放。深色模式桌面截图已核对，播放设置使用与软件设置一致的圆角面板、主题边线、下拉框和关闭按钮。

### 暂停逐帧时的亮度

在 Windows SDR 输出上，普通播放由 libmpv 把 BT.709 视频转换到 sRGB。连续按 D/F 时，播放器也可能显示独立解码器预先准备的相邻帧。旧缓存只做了视频范围扩展和 YUV 到 RGB 的矩阵转换，暗部因此偏亮。现在两种缓存路径（缩放后的 RGB 图像、按需解包的 10 位图像）都在高精度 RGB 上完成 BT.1886 到 sRGB 的转换，最后才量化为 8 位。只有明确标记为限幅 BT.709 的匹配素材才使用这条缓存路径。HDR10 输出由原生播放器处理。

使用真实的 3840 × 1632、60 fps、10 位 HEVC 原片验收。桌面测试 `videoReviewDisplayLevels` 在窗口和全屏各发送四次 F、两次 D，随后比较同一时间戳 00:05:41.233 的逐帧画面、原生暂停画面和播放画面。测试取窗口实际渲染的画面中央区域，避开字幕和控件，按 0–255 色阶计算 RGB 通道平均绝对差。可通过 `FORMAVIEW_REVIEW_COLOR_VIDEO` 指向原始测试文件复测。

| 修复前，逐帧与原生暂停 | 10.58 | 9.37 |

## 桌面 MCP 的开关与重连

Windows 开发包自带独立 stdio 程序。软件设置中的 MCP 开关同时应用目录范围并启动共享。每次开启使用新的本机命名管道；固定的客户端配置通过当前用户的连接文件查找活动端点。关闭后停止监听、释放连接文件，其他窗口可以接管。同一客户端进程可以保持打开，下一次工具请求会重新解析活动端点。

桌面回归 `mcpSwitchReconnect` 实际点击开关，使用内置适配器完成 MCP 握手和能力查询，验证关闭后请求返回错误，再次开启后同一客户端通过新端点成功查询。客户端首次注册和从旧版固定管道配置迁移均只需复制一次；独立后台模式仍按自己的客户端配置启动。

## MCP 批量转换验收（Windows x64，2026-11-26）

通过 stdio 客户端和本地任务服务实测了以下导出流程。

- 图片批量预检将 RGBA PNG 和 RGB JPEG 分别映射为四通道和三通道 TIFF。提交前目标目录未出现计划文件，提交后使用 Pillow 回读，尺寸和像素均与各自输入一致。空列表、超过 64 项、同名目标及越界输入均已覆盖。底层 11 类输入 × 9 个目标格式的 99 组转换也通过了独立回读。
- 模型批量预检将静态 OBJ 和带多个动画片段的 GLB 分别导出为 Unreal 坐标、厘米单位的 FBX。保留动画和仅导出模型各执行一次，第二次使用重命名冲突策略。FBX 回读验证了网格、单位和动画栈数量。Alembic 另取第 2 号采样（从 0 计），验证了源采样记录和静态网格输出。

可通过 `tests/image_batch_mcp_tests.py` 和 `tests/scene_export_mcp_tests.py` 复测。后者使用 `--abc-fixture` 指定至少含三个采样的多边形缓存。
