# v0.2 桌面使用便利性与适配调研

2026-11-25。以 Windows x64 的 v0.2 开发版为基线，检查了素材浏览、文件标签、播放信息、安装关联和现有验收记录。优先级按操作频率、已有用户反馈及能否用真实文件验证来排。以下判断来自源码、使用反馈及公开文档，未做用户访谈。

| 场景 | 已有能力与缺口 | 本轮决定或下轮验收方法 |
|---|---|---|
| 反复对比几个文件 | 标签按打开顺序排列，悬停可关闭。此前要切换到屏幕外的标签，通常需要回到标签栏寻找。视频检查时标签栏还会隐藏。 | 在检查页提供正反向循环和关闭当前文件的快捷键。最后一个标签关闭后回到浏览，保留工作区窗口。 |
| 分屏时辨认同名素材 | 浏览页在宽度低于 1080 个逻辑像素时收起检查器。来自不同目录的收藏可能显示相同的文件名。 | 窄窗底部显示选中素材的路径，长路径中间省略。悬停或键盘聚焦素材卡可查看完整路径。 |

| 小屏、高 DPI 与三种界面语言 | 主窗口最小逻辑尺寸为 760 × 580。像素分辨率相同的显示器，在不同缩放设置下能容纳的面板宽度不同。 | 覆盖 760、820 和 1080 的临界宽度，组合英文长标签、简繁中文路径和键盘导航。跨屏移动后检查弹窗位置、控制栏命中与选中项可见性。记录逻辑宽度和实际 DPR。 |
| 换机器后视频播放异常 | 已有 Tab 播放信息、硬件解码状态、丢帧数据和长 FLV 回归。现有开发机结果不能回答集显或不同解码路径的表现。 | 下一轮选集显与独显各一台，用同一 4K HEVC、长 FLV 和变帧率样本，对照硬解状态、远跳耗时、可见帧时间和音画同步。收集问题时附版本、解码器、渲染器和屏幕缩放，默认省略私人文件路径。 |

## 本轮实测

Windows 11 x64、Qt 6.12 Release、D3D11。应用与桌面测试程序均已构建。在同一台显示器上分别按系统 150% 和 Qt 等效 100%、200% 运行，窗口采集记录的 DPR 分别为 1.5、1.0、2.0。三组均通过以下四项桌面回归。

- 用两个不同目录的 PNG 测试正向及反向切换、关闭当前文件、关闭最后一个文件并返回浏览。
- 在 1600 × 900 与 820 × 620 逻辑尺寸下操作素材浏览器，检查窄窗选择摘要与源路径一致，并采集窗口截图。
- 通过键盘进入桌面目录，检查后退和前进时的目录、选择与滚动位置。
- 检查设置页的导航及草稿行为。

以上覆盖单屏布局。混合 DPI 双屏迁移、普通用户安装升级和跨显卡解码仍待实机验证。

## 参考依据

Windows 文件资源管理器使用 Ctrl+W 关闭当前标签。PowerToys Peek 把文件间导航和预览内容内的操作分开。FormaView 已把方向键用于视频跳转、D/F 用于逐帧，本轮将文件切换安排在 Ctrl 组合键上。[Windows 快捷键](https://support.microsoft.com/en-gb/accessibility/windows/keyboard-shortcuts-in-windows) · [PowerToys Peek](https://learn.microsoft.com/windows/powertoys/peek)

Qt 6 在 Windows 默认感知每个显示器的 DPI。QT_SCALE_FACTOR 会与屏幕的原生缩放相乘，适合复测布局断点。实机跨屏还需验证窗口迁移及焦点。[Qt High DPI](https://doc.qt.io/qt-6/highdpi.html)
