## 本轮实测

Windows 11 x64、Qt 6.12 Release、D3D11。应用与桌面测试程序均已构建。在同一台显示器上分别按系统 150% 和 Qt 等效 100%、200% 运行，窗口采集记录的 DPR 分别为 1.5、1.0、2.0。三组均通过以下四项桌面回归。

- 用两个不同目录的 PNG 测试正向及反向切换、关闭当前文件、关闭最后一个文件并返回浏览。
- 在 1600 × 900 与 820 × 620 逻辑尺寸下操作素材浏览器，检查窄窗选择摘要与源路径一致，并采集窗口截图。
- 通过键盘进入桌面目录，检查后退和前进时的目录、选择与滚动位置。
- 检查设置页的导航及草稿行为。

以上覆盖单屏布局。混合 DPI 双屏迁移和跨显卡解码仍待实机验证。

## Windows 普通账户升级

2026-11-25，在 Windows Sandbox 中从管理员组移除来宾账户，再用新登录令牌运行 v0.1.2 正式安装包和 v0.2.0 开发安装包。令牌包含 Users 组和 Medium 完整性级别。两个安装器使用同一账户的默认安装目录。

旧开发包 `8c2f640` 有一个可复现的问题。测试账户原本双击 `.pskx` 会直接打开已有的第三方查看器。升级时勾选该格式后，原打开命令仍在，双击却出现了应用选择器。单独撤掉 FormaView 的 `OpenWithProgids` 候选可以恢复 Windows 查询到的处理程序，但实际双击仍可能出现选择器。撤掉对应的 `Capabilities\FileAssociations` 登记后，第三方查看器才直接收到文件。Windows 会在新程序登记文件类型后提示用户选择应用。[Windows 默认应用机制](https://learn.microsoft.com/en-us/windows/apps/develop/windows-integration/default-apps-platform)

修复后的按用户安装保留已有的第三方传统打开命令。遇到这类关联时，安装器跳过上述两项候选登记，保留 FormaView 自己的类型说明、分类图标和打开命令。用户仍可右键文件，通过“打开方式”选择程序。修复安装只清理所有权账本中与当前值相符的旧候选。

| 实测项目 | Windows 11 x64 build 26100 结果 |
|---|---|
| Explorer 图标视图，关闭缩略图 | 全新沙盒从 v0.1.2 升级后，PNG、DDS 显示山景，FLV 显示播放三角，FBX 显示立方体，第三方处理的 PSKX 保持其程序图标。三个分类 ICO 的实际文件内容均与仓库资源的 SHA-256 一致。 |
| 原程序实际打开文件 | 升级时同时勾选 PSKX。升级前、升级后和卸载后，使用 Windows Shell 的普通打开动作，第三方测试查看器三次均收到对应文件的完整路径。覆盖安装修复已出现竞争登记的开发版后，也验证了真实打开动作。 |
| Windows 已保存的默认选择 | PNG、JPG、MP4、FBX 原有的非空 `UserChoice` ProgID 与 Hash 在升级和卸载后逐项一致，FLV 和 PSKX 原先为空的选择保持为空。沙盒中的部分 AppX 登记缺少可执行应用，因此打开行为单独使用上述可运行的第三方查看器验证。 |

验收安装包的安装器提交为 `8f94d0d`，复用已验证的 `8c2f640` 开发运行时，安装包 SHA-256 为 `b46d8402b5a7d287b817c99454426a1630bbba8dc75405c3b9439b2dff9a71f1`。复测脚本见 [verify_shell_upgrade.ps1](../tools/installer-ui/verify_shell_upgrade.ps1)。截图、安装日志与结构化结果存于发布暂存区 `verification/Shell-Upgrade-Icons-20261125/final2/results`。本轮验证范围是按用户安装、图标视图和同一显示器。

## 参考依据

Windows 文件资源管理器使用 Ctrl+W 关闭当前标签。PowerToys Peek 把文件间导航和预览内容内的操作分开。FormaView 已把方向键用于视频跳转、D/F 用于逐帧，本轮将文件切换安排在 Ctrl 组合键上。[Windows 快捷键](https://support.microsoft.com/en-gb/accessibility/windows/keyboard-shortcuts-in-windows) · [PowerToys Peek](https://learn.microsoft.com/windows/powertoys/peek)

Qt 6 在 Windows 默认感知每个显示器的 DPI。QT_SCALE_FACTOR 会与屏幕的原生缩放相乘，适合复测布局断点。实机跨屏还需验证窗口迁移及焦点。[Qt High DPI](https://doc.qt.io/qt-6/highdpi.html)
