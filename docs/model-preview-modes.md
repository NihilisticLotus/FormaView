# 模型预览与显示模式

v0.2 检查工作区在宽视口底部直接列出五种显示模式。新打开的模型默认收起地面网格和坐标轴，可在视口底部单独开启。空间紧张时点击当前模式图标，或聚焦后按向下键展开菜单，用方向键选择、回车确认、Esc 关闭。

| 模式 | 行为 |
| --- | --- |
| 材质 | 使用预览工作室灯光显示原材质、贴图和透明度。 |
| 棋盘格材质 | 忽略原材质及透明度，使用带光照的程序化灰色棋盘格；有 UV 时按 UV 显示，无 UV 时根据表面方向投影到模型空间。采用导数过滤降低远处闪烁。 |
| 素模 | 使用统一的中性材质和光照观察表面起伏。 |
| 顶点色显示 | 忽略材质、贴图、光照和透明度，显示第一组源顶点 RGB；未提供该数据时使用中性灰，不将材质色冒充顶点色。 |
| 线框显示 | 沿用现有 GPU 线框实现，并使用可见的浅色、不透明线条。 |

FBX 从 `colour/0` 读取第一组角点色，glTF 从 `COLOR_0` 读取，ActorX 从 wedge 颜色读取。颜色以独立属性传入静态、GPU 骨骼和流式几何渲染；保留原默认着色数据。当前未解码源颜色的适配器显示中性灰。顶点 alpha 不用于此 RGB 检查模式。

切换显示模式仅更新渲染状态，不重建模型、不移动相机、不修改原始文件及导出内容。打开新文档恢复默认。UV 视图、源权重热图、地面网格和坐标轴保持各自检查语义；线框仍可用于三维权重视图。棋盘格复用当前三维材质所选 UV 与其变换，不替代独立 UV 检查视图。

### 骨骼、绑定与 LOD

「骨骼」和「绑定」在三维视口叠加浅蓝色的父子骨骼连线。动画模型按当前姿态更新，选中的骨骼仍以橙色突出显示。「骨骼」视图左下角显示当前骨骼名称。连线依据源文件中的直接父子骨骼关系，刚体节点动画可能有可播放片段但没有骨骼连线。

「LOD / 碰撞」在视口内显示当前碰撞模式和可见三角形数。切回「模型」恢复常规视图。浅色和深色主题各自使用 HTML 原型的视口底色。

### 验证入口

- `formaview_model_render_tests OUTPUT_JSON`：实际 D3D11 像素回读，包括黑色/全透明材质下的独立 RGB、UV/空间棋盘格、不透明覆盖、UV 隔离及原材质回归。
- `formaview_model_state_tests FIXTURES UFBX_FIXTURES BLENDER_FIXTURES`：源顶点 RGB 与材质乘色分离、原模型状态回归。
- `FORMAVIEW_MODEL_PREVIEW_SAMPLE` 指向只读问题 FBX，设置隔离 `FORMAVIEW_UI_TEST_ROOT`，运行 `formaview_desktop_tests modelPreviewDisplayModes`：五种模式、紧凑菜单、相机/几何不变、文档复位及截图。
- `formaview_model_gpu_tests SAMPLE OUTPUT_JSON 1 numeric`：既有骨骼 GPU 与 CPU 数值对照，覆盖新增顶点布局。

v0.2 第四阶段使用 HTML 原型中的同一份 `RobotExpressive.glb` 对照，原型列出 14 个片段，桌面端打开后选中 `Idle`，视口显示 3,237 个三角形。用 `FORMAVIEW_REVIEW_ANIMATED_MODEL` 指定该文件或 `Cheering.fbx`，运行 `formaview_desktop_tests modelAnimationInspectorControls` 可复查动画检查器、步进与拖动定格、LOD 切页及截图。有蒙皮绑定的样本还检查骨骼连线。Windows Release 下分别验证了 D3D11 GPU 蒙皮与强制 CPU 回退。

原始问题样本：`SK_Claymore_PhantomCicada.FBX`，27,733 点、31,715 三角形。样本及测试截图、日志仅保存在忽略的本地 `development/` 中。

三维视口的 N 和 T 可独立开启。蓝线为法线，红线优先显示源切线，缺失时用当前 UV 集计算。状态行标明切线来源。网格按三角形角点取样，最多选取 512 个三角形；动画随当前姿态更新。

### 第四阶段的视口与连续切换

- 打开模型或按 Home 时采用与 HTML 原型相同的 38° 垂直视场和初始观察方向。取景距离按模型包围球和窗口宽高比计算，窄窗口也能显示整个模型。
- 三维视口以源坐标地面为基准显示随距离淡出的地板。材质和素模使用暖色主光、冷色补光与半球环境光。顶点色和权重仍可独立检查。
- 「LOD / 碰撞」在画面中显示可见网格数、网格总数、三角形数和碰撞模式。如果筛选使可见网格降为零，点击「显示可用网格」会取消隔离、选择各组最低编号 LOD，并叠加碰撞网格。「骨骼」可在视口内清除当前选择。
- `modelSwitchDuringDocumentNotification` 在模型加载完成的通知中交替打开动画和静态 glTF，共落地 20 次，并穿插播放、切 UV 和最后关闭。加载结果现在先从队列取出，再通知视图，避免下一次打开扩容队列时使旧迭代器失效。

修复前，这个回归用例可复现进程异常退出，调试器停在堆释放路径。此前那次用户现场退出只有堆损坏记录，缺少能对应到模型切换的转储，无法确认两次调用栈相同。

在工作区从文件打开通知中立即切换下一个模型时，任务队列可能扩容。工作区现在先取得已完成任务的副本，再发出通知，新请求由下一轮处理。`modelSwitchDuringAssetPublication` 通过正常打开文件入口连续交替打开 20 个请求，并检查最后一个模型能进入检查状态。使用旧版工作区队列运行同一用例可触发访问异常。

2026-11-23 继续排查 GPU 路径时，调试器捕获到另一处 `0xc0000374`。调用栈位于 GUI 线程的 `QQmlIncubatorPrivate::incubate`，释放的 224 字节孵化器对象已被堆标记为 free。原检查器只在模型 `available` 时保持活动，新模型加载期间会销毁尚未完成创建的检查器及其嵌套加载器。GPU 与 CPU 的准备时序不同，不能把 CPU 通过解释为 GPU 蒙皮数值错误。

检查器现在与预览面板一致，在模型加载、就绪和读取失败之间保留同一个实例；清空文件或离开模型后仍释放。GPU 蒙皮保持启用。`modelPanelIncubationCanBeCancelled` 控制异步创建预算，验证切换不会取消正在创建的检查器，而关闭文件仍可取消。`modelGpuSwitchPlaybackStress` 在真实 FBX、静态 glTF、PSK 加 PSA、动画 glTF 之间循环六轮，共 24 次打开，检查同一检查器、实际 GPU 蒙皮数据、帧呈现和动画推进。设置 `FORMAVIEW_SKINNING=cpu` 可运行同组对照。

恢复旧检查器条件后，上述两项回归均失败；修复版通过。原崩溃序列 `modelGltfLodPreview modelAnimationAvailability` 在 D3D11 下连续 30 个独立进程通过。证据、调用栈与转储保存在仓库外的 `asset-preview-planning/development/verification/Model-Animation-Inspect-20261123/`，不随程序分发。

### 用原型样本检查 LOD 与碰撞

打开 `LOD_Collision_Study.gltf`，选择「LOD / 碰撞」。检查器顶部列出等级和当前可见的表面、碰撞三角形数。每个等级直接列出部件数和相对首级的三角形比例。有碰撞部件时还会列出对应的数量和面数。这个视图用青色线框绘制已确认的碰撞几何，选中的碰撞网格更亮，可以透过线框检查模型表面。

| 显示等级 | 该等级的三角形 | 场景可见表面三角形 |
| --- | ---: | ---: |
| LOD 0 | 960 | 1,068 |
| LOD 1 | 224 | 332 |
| LOD 2 | 48 | 156 |

这个样本每个等级都额外显示 108 个未分级的三角形。桌面端读取当前场景节点的可选 `MSFT_lod.ids` 关联，子节点继承所属等级。引用互相冲突时保留普通几何，名称中的 LOD 或碰撞前缀只作为候选提示。切换等级后可在「网格归类」选中被筛掉的网格，点击「显示此网格」恢复它所属的等级和必要的碰撞显示方式。网格已经可见时，同一位置提供「聚焦此网格」。

将 `FORMAVIEW_GLTF_LOD_SAMPLE` 设为原型的该样本，运行 `formaview_desktop_tests modelGltfLodPreview` 可复查三个等级、碰撞分项计数、恢复所选网格以及嵌套和冲突的源关联。


### 材质检查与会话贴图

「材质」检查器可选择当前目录或已添加素材中的图片，也可使用「定位贴图」。关联按文档内的源材质标识分组：glTF 使用源材质索引，FBX 使用解析器的材质对象 ID。一次关联或清除会同步所有引用该材质的网格；面板列出受影响网格。同名但不同 ID 的材质保持独立，未提供可靠标识的格式按当前网格材质槽处理。

关联使用所有共享网格均具有的有效 UV 通道，按通道名称匹配，不依赖各网格的数组顺序；任一共享网格缺少该通道或其数据无效时，禁用关联，避免只更新部分网格。面板分别显示源基础颜色贴图引用、已经验证的显示贴图和正在读取的请求文件，避免把尚未成功读取的路径当成已应用结果。

读取中可取消，失败或取消后可重试。两种情况都保留之前显示的贴图；重试使用原请求的文件和 UV 集。取消、关闭文件或切换模型后，旧请求的迟到结果不会覆盖新状态。「清除会话关联」恢复源贴图与参数，不修改源模型或图片。

「源贴图 UV 变换」展开后显示源 UV 集和 2 × 3 仿射矩阵。FBX 使用适配器提供的仿射变换，glTF 的偏移、缩放、旋转转换为同一矩阵表示；适配器未提供数据时明确显示未提供。会话关联不覆盖这组源数据。

通过 FORMAVIEW_MULTI_UV_SAMPLE 指定原型 MultiUV_TestPlane.gltf，运行桌面回归 modelMaterialWorkflow，检查工作区图片关联、源变换、失败保留、取消迟到结果、原 UV 重试、清除恢复和源文件不变。

### 源相机控制

「场景 → 资产相机」提供相机选择、进入/退出源相机视图、视锥与轨迹独立开关，以及框选相机与模型。进入后保留源透视或正交投影及画幅比例，在视口中留边；glTF 未指定宽高比时跟随视口，未指定远裁剪面时使用无限远投影。无效投影或奇异变换不能进入源相机视图。

时间轴驱动相机和父节点的源动画，轨迹按当前片段采样并包含两端，每台 glTF 相机最多 241 点。源位置、轴向、FOV、裁剪面与镜头参数独立显示，缺失焦距不会被默认值冒充。FBX 沿用 ufbx 求值，Alembic 跟随当前已呈现的采样。

源相机视图中禁用自由旋转、平移和缩放，隐藏辅助视锥、轨迹、地板与坐标轴。返回自由视图恢复原取景；Esc 返回，F/Home 退出后聚焦。切换文档清除相机视图与辅助显示开关。相机只影响预览，不写回源文件；源读数不包含居中或根运动锁定。

通过 FORMAVIEW_CAMERA_MATERIAL_SAMPLE 指定 HTML 原型 Camera_Material_Study.gltf，运行 modelSourceCameraAndSharedMaterial，可验证投影、画幅、父节点动画、共享材质取消/重试/清除、同名不同 ID 隔离及 UV 顺序映射。camera_preview 覆盖 FBX/Alembic 的纯相机与混合场景。
